## 架构

本机 Node 常驻服务持有官方 SDK、加密凭据读取与累计预算账本；Windows 原生 broker/worker 负责 UI Automation、输入与窗口绑定，Python 进程不接收真实 API Key。一次有界任务在本机循环内完成多步，不逐次返回聊天等待下一次点击。

独立 Chrome 使用 Playwright；内置浏览器保留 CUA 适配器。桌面截图增加 mss/GDI 后备路径，并遮住账户栏。本地 OCR 已实测；官方 Jev 图片定位已实测为目标建议，自动坐标点击尚未激活。

## 浏览器速度结论

独立 Chrome 首次提交查询，含 Google 首页加载约 4.05 秒，其中观察 38 毫秒、Jev 1.104 秒、输入提交 183 毫秒；随后出现 Google 异常流量验证，由用户手动完成。恢复后进入图片结果页 7.166 秒，再连续保存三图 1.503 秒。人工验证时间和两次调用之间的人为停顿不能合并成自动执行速度。

内置浏览器单次 DOM 读取仍约 21 秒。“点击图片”本地循环共 85.893 秒，其中 Jev 365 毫秒。其原生 downloadMedia 后续跳到图片 URL，最终报告下载超时；该轮从观察到失败记录共 207.029 秒。核对 URL 和下载目录后，Codex 返回结果页、重新读取实际图片来源并保存。恢复中的返回与来源读取工具调用约 52.46 秒，另有检查资源清单和页面的两次约 21 秒读取。

因此，1.141 秒仅是内置路径恢复后的保存段，不能宣称内置浏览器全流程只花一秒。原生 downloadMedia 本轮 0/1，后备保存 3/3；这正是应触发 Codex 接手的场景。网页默认优先独立 Chrome，用户指定内置浏览器时保留该路径与独立计时。
