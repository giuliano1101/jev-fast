# Working with jev-fast

Read [the agent quick start](docs/quickstart-agent.md) before connecting. Operator setup is in [the control panel manual](docs/control-panel.md) and [the CLI/MCP manual](docs/cross-machine-cli-mcp.md).

For remote hosts, start with [manual admission](docs/manual-admission.md) and the [deployed service guide](docs/public-service-quickstart.md): AI/device connections require no user-managed network key or login, are displayed by self-reported name, and default off until the operator enables that connection instance. Names are not verified identities; opaque session/registration handles remain internal capabilities. Operator controls stay loopback-only. One selected executor and multiple AI sessions are supported, with distinct request/owner scopes and cancellation generations. The old [Bearer network mode](docs/network-mcp.md) remains optional. Six network action tools require `{request_id, params}` wrappers plus two read-only status tools; local stdio/CLI schemas stay unchanged. Preserve business IDs and UNKNOWN semantics, never self-approve or use the operator API from an AI tool. Local global stop overrides remote work. Public Ubuntu relay TLS/SDK/default-off/management isolation and unapproved connector heartbeat recovery are verified. S17 additionally verified one approved real Jev synthetic goal over the public MCP route; physical second-machine acceptance remains unverified. The current operator has explicitly enabled an external local auto-admission program for all AI names; this is an operator deployment policy, not permission for an AI tool to call the operator API. See the deployed guide for current state.

- This is an experimental, bounded execution service. The main CLI/MCP supports only the `standard` local synthetic fixture and its twelve fixed tasks. Historical website/Android research adapters are separate; do not claim arbitrary website, desktop or phone support.
- The original operator Mac is a shared live service: `/tmp/jev-501`, real remote Jev, private operator-provisioned profile. Other AIs must reuse it and must not stop/restart it during cleanup, switch its provider, request its model key/profile from the user, or reset its budget. The operator keeps responsibility for private configuration and allowance. The operator subsequently explicitly removed paid cost/request-count/expiry limits: the current deployment uses usage-only metering. Reuse this provisioned policy without asking other AIs/users for new paid approval; do not restore the superseded S17 caps or alter historical ledgers. Verify actual health; scope remains standard fixtures, not general desktop support.
- Default for new installations is offline `mock`. Reading this repository, starting the panel, or possessing an API key does not authorize hosted spending. Remote Jev requires operator-provisioned private configuration, enrollment, certificates, token and an explicit operator spending policy (capped approval or usage-only metering). Never create or reset approval counters on behalf of an agent.
- Start the local coordinator before connecting an MCP stdio facade. Use Node 24.19+ and absolute executable/entry/credential paths in host configuration. `scripts/env.sh` belongs to the original development machine only.
- Use `doctor`, `policy status` and `schemas --json` to check the actual installed build, provider, identity, health and contract. CLI and MCP share the same coordinator. Provider selection and operator controls are not ordinary tool arguments.
- Keep goal IDs and idempotency keys stable across uncertain transport responses. Query status before retrying. `UNKNOWN` means stop and preserve the audit; never replay with a new key. `FALLBACK` does not authorize switching to another control tool.
- Keep credentials, profiles, runtime ledgers and raw user data out of Git, chat, reports and model prompts. Do not delete audit state to recover from errors.
- Stopping the coordinator prevents new actions in that service and cancels/drains its work; it does not disable other host tools or reverse completed physical actions.

For code changes: use the applicable Superpowers engineering skills, test meaningful behavior, and run `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:integration`, and `npm run test:safety` before claiming completion. No hosted calls in ordinary tests or CI. Document scope limits alongside results.
