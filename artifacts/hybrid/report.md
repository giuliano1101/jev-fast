## 故障覆盖

| 场景 | 验证结果 |
|---|---|
| 首次任务/过期/范围不匹配 | 请求 teacher 或有界停止，不直接复用旧流程 |
| 三次独立成功、两个起始状态 | 激活原流程；已经完成的前缀不造成错误修订 |
| 低置信度/无效选择/模型异常 | 不盲点、不反复请求；最多一次 teacher 接管 |
| 暂时不可见/加载 | 只读等待；unknown 不当作 false |
| 条件稳定后确实丢失 | 检测回归并隔离规则，接管受相同预算限制 |
| 结果不明/迟到响应/进程重启 | 未决记录保持隔离，后续运行没有物理输入 |
| 不允许重复的动作 | 同一任务第二次物理尝试被阻止 |
| 死线/取消/租约冲突/存储错误 | 有界停止或 UNKNOWN，不能报告成功 |
| 重复证据/容量上限/文件损坏 | 拒绝写入或打开，保留既有数据 |

## 与抖音问题对应的浏览器回归

`fixtures/hybrid-flow.html` 模拟“排序可能影响已发布、图文筛选”，真实 Chromium 操作按钮并独立读回状态。

- 短暂重绘：排序后两个标签暂时消失，随后自行恢复。最终仅点击排序 1 次，筛选点击 0 次。
- 持久重置：排序后两个筛选确实保持关闭。最终排序 1 次、已发布 1 次、图文 1 次，三个条件同时成立。

这证明实现能区分这两种受控情况；不能据此断言抖音平台必然重置筛选，也不能保证任意 UI 完美操作。观察器必须正确报告就绪和未知状态。

## 审查与边界
