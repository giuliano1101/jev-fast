# Jev 真实浏览器对比报告

日期：2026-10-30，Asia/Shanghai（UTC+08）。正式评测于 04:45:56–04:46:57 完成。真实 TypeSafe API、真实浏览器操作；页面为本项目的合成任务。

**结论：受限任务上有明显速度优势，高难度稳定性仍不足。** Jev 正式评测完成 25/30（83.3%），普通 Codex computer use 完成 18/18。双方共同的 18 项中，Jev 完成 16 项；这 16 项均无页面误操作，逐项计算「computer use 耗时 / Jev 耗时」的最近秩中位数为 **5.49×**。另外两项失败保留在可靠性分母中，不进入成功速度比。不能把这个比值解释为所有任务均加速 5.49 倍。

## 稳定性与失败

- 正式 Jev 30 项记录 0 次页面误操作，5 次 `LOW_CONFIDENCE` 停止，0 次 `UNKNOWN`，0 次 API 错误。共 84 次正式 HTTP 请求。
- 困难定位成功 3/5，困难表单成功 2/5。定位的两次停止置信度为 0.81、0.68；表单的三次停止发生在滚动到复核框之前，置信度为 0.88、0.88、0.82。执行阈值始终为 0.90，没有为了提高成绩放宽。
- 事后对照可见指令，这 5 个被拒绝候选与下一步意图相符；这只能说明本次置信度门控拒绝了有用候选，不能据此认定模型置信度已校准，更不能据此降低所有场景的阈值。
- Jev 另有 7 次动作前状态过期拦截，重新观察后继续；总 rejection 数 12 = 7 次过期 + 5 次低置信度。没有重放结果不明的物理动作。
- 普通 computer use 全部完成，但有 2 次工具调用错误（页面重绘导致旧节点失效、滚动节点失效），重新观察后恢复；这不是“全程无错误”。
- `wrong_actions` 只统计诱饵点击和页面拒绝的错误推进，不涵盖每次临时字段编辑。不能将 0 次页面误操作解释为所有低层操作绝对正确。

样本很小：Jev 总成功率的 Wilson 95% 区间约 66.4%–92.7%，困难组约 23.7%–76.3%；普通 computer use 的 18/18 对应约 82.4%–100%。本实验没有证明长期生产稳定率。

## 任务与公平性边界

定位任务覆盖精确标签、相同按钮下的多条件卡片选择、250 ms 后重绘与二次复核。表单任务覆盖填写、下拉选择、多步确认、800 ms 延迟加载、复核框与长页滚动。两类任务各三档难度；Jev/脚本评测 seed 1–5，普通 computer use 为同任务 seed 1–3。

普通 computer use 由独立操作代理只读可见指令与 AX/DOM 控件完成，没有查看源码、答案标记或隐藏评分状态。评分来自独立页面 oracle，并与操作代理的可见完成记录交叉核对。原始操作记录见 [operator.json](../computer-use/operator.json)，页面评分见 [scores.json](../computer-use/scores.json)。

Jev 使用固定 `jev-1.14.0`，由本地适配器将可见状态转成有界候选，填写值从可见合成指令提取。它使用 Playwright Chromium 148，900×600；普通 computer use 使用当前 Codex 会话的 IAB、AX/DOM 工具。因此比较的是完整操作路径，不是相同模型、相同浏览器、相同工具条件下的纯模型速度。

主计时从页面脚本初始化至成功或停止，包含页面延迟、模型/工具往返、恢复和操作期间的调度；不包含页面初始化之前的浏览器启动与导航，也不包含完成后的结果读取。普通组第一项包含一次绑定恢复，部分操作期间有进度说明；未删除这些样本。两组分批执行，没有随机交错，网络与会话开销也是局限。

本次为独立 **12 步 / 120 秒研究工具**，不是已交付 **8 步 / 60 秒 P0 引擎**的性能验收。未测试日常用户网站、真实账户或原生 macOS 应用，不能外推为全电脑控制速度。

## 校准及已落地改动

正式评测前的 seed 101 校准为 3/6 成功，三个表单因低置信度停止。改动包括：去掉填写当前相同值、选择当前相同选项等确定性无效动作；在状态摘要保留实际字段、选择和勾选状态；明确按可见步骤推进、避免重复已完成步骤。没有删除其他有效选项，也没有读取隐藏 oracle 生成答案。

改动后使用新的 seed 102 校准，5/6 成功，三档表单全部完成，一项困难定位低置信度停止。随后冻结源码与执行文件 hash，再运行 seed 1–5 正式评测；没有根据正式失败重新调参或挑选重跑。两轮校准的原始记录和费用均保留。

此前完成的官方 SDK 与 GitHub 同类项目对照、批量状态读取和 zstd 请求压缩见 [优化对照文档](../../../docs/optimization-review.md)。本轮真实 smoke 同时验证了普通 JSON 与 zstd 请求可被服务接受；冷连接差异使这两个单次耗时不能证明压缩加速比例。

当前更适合将 Jev 用作明确、受限步骤的加速执行器。下一步应评估低置信度时交回主 computer use 的混合策略，并在独立新任务上计入回退耗时；本次未实现或测量这种混合策略，不能承诺其成功率或总体加速。
