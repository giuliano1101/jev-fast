# S9 安卓真实交互对照报告

日期：2026-10-30。实体 OPPO Find X3 Pro / Android 12，Mobile MCP 1.0.8。普通 Mobile MCP 组由当前 Codex 助手读取实时控件、选择动作；Jev 组使用真实 `jev-1.14.0` 选择固定目录中的候选，确定步骤由本机执行，两组都通过同一个 Mobile MCP 操作手机。

第一版普通组 **12/12 成功**，Jev v1 **10/12 成功**。双方成功的 10 组配对，完整工作流耗时比中位数 **2.42×**。这不代表 Jev 模型本身快 2.42 倍，也不能忽略两次失败。绑定加固后 v2 **12/12 成功**；12 组双方成功配对耗时比中位数 **2.97×**。原失败记录不覆盖。

## 准确率与问题

M5 第一轮、M6 第二轮：`select_font` 点击回执成功，后验仍是搜索页，执行器停止并请求接管；实际没有配置 teacher，结果为 `TEACHER_UNAVAILABLE`，两次均保留为失败。没有再次点击或继续后续操作。页面后验比工具回执更重要。

补充诊断的宿主固定计划 M3 6/6、真实 Jev M5 4/4 成功，未复现历史失败；8 次字体目标点击的实际坐标与观察目标中心一致。因此历史根因尚未确认。底层 ref 点击重新读取并编号 UI 的行为确实存在绑定风险，v2 针对该风险进行硬化。详见 [诊断记录](diagnosis.md) 和 [补充诊断汇总](diagnostic/summary.json)。补充成功不加入正式分母，不替换原失败。

前期发现并修复的其他问题：M5 跨应用返回可能回到搜索页而非字体预览，加入条件恢复步骤；浏览器加载可能超过 2 秒，将手机有界等待配置为最多 10 秒 / 6 次观察；M5/M6 不能靠乱序“访问过页面”满足任务，必须核验动作与页面顺序。浏览器首次较慢的 smoke 失败也保留在 [smoke/](smoke/)。

## 测量方法与限制

普通组完整耗时包含助手思考、Codex 调度、MCP 执行、观察及最终记录；Jev 组包含控制器、模型请求、MCP 执行和验证。普通组 MCP 工具耗时另外统计；两者差值不能解释为纯模型推理时间。Jev 的 `result.elapsedMs` 用于配对；`elapsed_ms` 另含起点预检，两者均不含 SDK 建连。复位独立记录，不计任务耗时。

普通组先运行，v1 随后运行，没有交错随机化；同一手机、固定已知任务，每题仅两轮。顺序、缓存、学习、网络与宿主输出长度均有影响。前两题与后续题输出长度不同，异步工具取回也计入普通组工作流。成功配对速度与全部试验成功率必须一起阅读，不外推任意手机或任务。

执行器使用受信任固定目录模式，未把开发者编写的题目伪装成自动学习出的 ACTIVE 流程。自动 teacher 交接、学习晋升在 S8 已有离线验收，本轮实机没有配置真正的自动 teacher 修复；不能声称已经证明手机上自动踩坑学习的全链路。
