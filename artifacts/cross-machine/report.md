设备私钥目前使用本人所有的 0600 私有文件；**尚未接入操作系统 Keychain**。宿主工具也未隔离，因此健康信息始终明确 `advisory-only`。同一用户下的恶意进程不在本阶段安全保证内。中央服务有界限流、满载拒绝，未实现公平排队和长期存储自动归档。

## 测试题目与结果

本阶段重点是可靠性，不是重新测量 Jev 加速比。测试全部使用临时本地服务、合成浏览器和假 hosted 传输，没有新增付费请求。

1. **双逻辑设备并发填表：** 两个独立浏览器和两个身份连接同一 TLS 网关，分别执行不同 seed 的 form 任务；两端均 SUCCEEDED，动作账本的设备/会话和签名许可分别匹配本端。
2. **设备隔离：** B 查询或取消 A 会话、复制 token 到另一证书、伪造/过期/已撤销身份都不能获得执行能力。
3. **相同请求重复提交：** MCP 完成后从 CLI 共用的 IPC 入口提交同一请求，返回原结果，无新增动作；中央重启后返回原签名回执，不再预留预算。
4. **网络失败与 UNKNOWN：** 请求中断、供应商响应不明、执行后响应丢失保留 UNKNOWN；重启及同键重试不重放。网关离线仍可查本地结果并停止。
5. **撤销竞态：** 上传途中、provider 运行中，以及 SQLite begin/reserve/complete 的等待窗口中撤销，都不能继续派发或返回新许可。
6. **执行许可有效期：** 签名篡改、身份/候选/实际参数绑定变化、旧租约、过期快照和本地时钟变化均拒绝；异步 adapter 校验耗尽许可时不得点击。
7. **存储故障：** 截断 JSON、合法 JSON 的非法引用、未来版本、SQLite 丢表/非法行、目录同步失败、锁清理失败及容量边界，不自动重置历史。
8. **模式与运维：** 无批准 live 拒绝、mock 默认离线、加载错误配置不泄漏内容、重复启动配置不一致拒绝、token 独占文件写入、在线登记/吊销及离线 stop。
9. **保留既有能力：** S6–S9 的单元、浏览器集成与安全回归全部运行，公开六工具定义未改。

## 账本容量实测

使用当前 v2 格式，单台 Mac / Node v24.19.0，每档一次样本。记录包括完整校验、打开恢复、一次事务、10,000 次索引读取；RSS 不是隔离峰值，且继承前一档进程状态。原始结果见 [ledger-capacity.json](ledger-capacity.json)。

| 历史动作 | 文件大小 | 校验 | 打开/恢复 | 单次事务 | 10,000 次索引查询 |
|---|---:|---:|---:|---:|---:|
| 10,000 | 5.97 MB | 67.97 ms | 164.51 ms | 84.07 ms | 14.64 ms |
| 100,000 | 60.69 MB | 469.54 ms | 1,627.96 ms | 907.22 ms | 13.52 ms |

索引改善了历史键查找，但完整 JSON 事务仍随历史增长变慢；10 万条时约 1.05 GB 进程 RSS、约 0.91 秒单次事务会明显消耗 2 秒快照预算。100,000 是保护上限，不是稳定运行推荐量。保留/归档和迁移策略见运维说明；没有通过删除幂等记录优化数据。
