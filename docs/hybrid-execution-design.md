# S8 设计：自动探路、规则验证与混合执行

状态：有界研究实现已完成，支持 teacher 回调、版本化流程证据和混合执行；实现范围与未实现项见 [实现说明](hybrid-implementation.md)。本文仍保留完整目标设计，不能将所有设计项视为已完成。S7 实测结果不变。

## 目标与证据边界

目标是提高完整任务的成功率，同时在重复任务中摊薄探路成本。不是要求 Jev 独自解决所有页面问题，也不是将失败停止包装成快速完成。

S7 当前代码与证据：

- `bench/real/session.ts` 已在每次动作前读取当前绑定、动作后检查结果，低置信度会停止。它还没有跨执行者的总预算、稳定状态屏障、teacher 接管或流程库。
- `bench/real/optimization.ts` 的阶段与批次由开发者写死，尚不是自动从示范学习。
- `bench/real/observation.ts` 的 completed 来自当前界面，有正确基础；仍需区分“明确为否”和“加载期间无法观察”。
- S7 最终 Jev 8/12，普通 computer use 12/12，样本很少。四次最终失败均是低置信度拒绝，不等于四次误操作。
- 抖音排序时曾观察到筛选标签变空。现有证据不能区分短暂重绘与持久重置。只能记录 `sort may invalidate filters` 的待验证假设；不能记录成网站一定会清空筛选的事实。

## 分工与统一执行入口

一个调度器管理三个路径，只有一个执行器拥有当前界面的动作租约：

1. **确定性路径**：经过验证、前提满足、目标唯一的步骤直接执行，不必为了点击唯一的正确按钮再次调用 Jev。
2. **Jev 路径**：当前存在多个合法候选、上下文匹配且能够验证结果时，由 Jev 选择。
3. **Computer-use teacher 路径**：首次遇到任务、流程过期、状态不符或 Jev 无把握时，teacher 观察、解释和制定下一步。teacher 的实际输入仍经过同一执行器、授权范围和预算检查。

teacher 是规划能力，不是更高权限。它不能修改成功标准、降低置信度门槛、扩大站点/账号/数据范围，也不能自行提高总动作数、截止时间或花费上限。切换执行者不创建新的预算或重试额度。

teacher 提交结构化候选与流程修订，执行器重新解析当前界面、绑定语义控件并验证。页面文字、历史截图和模型生成的规则都属于待验证材料，不是新授权。

## 自动触发策略

以下是首版可配置默认值，属于工程假设，不是由 S7 样本证明的最优参数。

| 触发事件 | 自动处理 | 恢复 Jev 的条件 |
|---|---|---|
| 新任务类型，或不存在匹配的有效流程 | teacher 处理首个真实任务，并记录轨迹；禁止为“踩坑”额外制造有副作用的操作 | 新流程通过学习门槛，进入受监督试运行 |
| 流程已验证，页面/账号范围/语言/控件语义均匹配 | 唯一确定步骤直接执行；存在选择时调用 Jev | 每步与任务末尾验证始终开启 |
| 新网页结构、缺失/重复目标、弹窗改变可操作区域、流程到期 | 暂停该流程，读取新状态，teacher 重新评估 | 修订版重新通过验证；不原地覆盖旧版本 |
| 首次 Jev 置信度 <0.90 或返回无效选择/概率 | 不输入、不重复询问 Jev；在预算允许时接管一次 | teacher 完成当前任务，或形成可验证的后续片段；原规则不得因一次 teacher 成功自动升级 |
| 操作后条件暂时不可见，页面正在加载 | 进入只读稳定等待，不能立即再点或判定条件丢失 | 目标区域就绪且相关条件稳定，或明确失败 |
| 稳定后发现原有条件确实失效 | 流程降级；有已验证且可安全重入的修复分支时最多执行一次，否则 teacher 接管 | 在稳定状态重新满足完整目标；修复效果进入证据 |
| 连续两次已确认动作没有推进，或同一状态循环 | 结束 Jev 路径，teacher 接管一次 | 仍未推进则停止该任务，不在两个执行者间反复切换 |
| 已开始输入但执行结果不明 | 隔离动作记录；仅允许只读核对是否已发生，禁止任一执行者直接重放 | 得到权威可见结果后按协议继续；否则返回 UNKNOWN |
| 授权、时间、预算耗尽，或遇到必须由用户处理的动作 | 有界停止，并保存原因和剩余工作 | 新的有效授权或用户操作；模型升级不能绕过此条件 |

调度判定优先级：授权/UNKNOWN → 总预算 → 当前状态就绪 → 独立终态验证 → 流程匹配 → 已验证修复分支 → 确定步骤/Jev → teacher。

单个原始任务最多一次 teacher 接管，不因接管重置累计动作数和时间。第一版继续采用总共 12 个物理动作、300 秒的上限；如果某类新任务需要更大范围，必须在任务开始前建立明确的新策略，不能在失败时临时放宽。

## 示范如何变成规则

不能要求 computer use 第一遍“把所有坑踩完”。第一次示范只能产生候选流程；它可能走运，也可能携带错误假设。

流程生命周期：

`UNSEEN → DRAFT → PROBATION → ACTIVE → QUARANTINED/EXPIRED`

- **DRAFT**：teacher 完成一次任务且独立验收通过，保存候选流程。没有经过验收的轨迹不用于学习。
- **PROBATION**：允许在授权范围内进行受监督验证；不算已学会。收集三次独立、经验证的执行，至少覆盖两个起始状态。包含第一遍示范，不能把三个步骤或三次轮询算成三次运行。
- **ACTIVE**：三次均成功、没有未决动作，流程结构合法、每步有可检查的前后条件和完成判据。三次是试运行入口，不代表统计上的高可靠率。
- **隔离**：出现一次确认的前提/不变量破坏、错误动作或证据矛盾，停止该版本的快速执行；对照原始轨迹定位原因。加载期间 unknown 不当作确认破坏。
- **过期**：原生版本、关键控件结构或权限范围变化立即过期；初始建议再设置最长七天的时间复核门槛，实际时长用后续变更数据校准。

前三次验证优先利用用户真实请求中的后续项目，不默认额外执行三遍。发布、付款、删除等不可安全重复的流程不得用真实账户反复试验；没有安全验证条件就保留 teacher 路径，不晋升。

ACTIVE 流程的前十次执行由 teacher 做只读结果审阅；随后默认抽查每十次一次、每批首项和环境变化后的首项。**抽查只减少昂贵的 teacher 审阅，不减少每步以及每项任务的确定性验收。** 抽查仍需具备该数据的访问/传输授权；没有授权则不能静默上传页面。

## 保存状态与依赖，不保存点击回放

每个流程版本保存以下内容：

- 匹配范围：站点/原生应用、页面类型、账号权限的本地不透明范围标识、语言、关键控件指纹、观察器版本。完整页面哈希不适合动态列表；只比较与任务有关的结构。
- 参数契约：目标值的类型与允许范围。比如“审核状态”“内容类型”“排序”，不把某个账户的数据或一次操作中的具体作品固化成规则。
- 目标谓词：可见、稳定、可独立判断的完成条件。未观察到的值记为 unknown，不自动记为 false。
- 步骤：动作的语义目标、前提、后置条件、可能失效的其他条件、允许的恢复分支、是否可安全重复。
- 依赖：只有具有证据的依赖才进入必选顺序；一次异常先登记待验证假设，不自动泛化。
- 证据：各次运行的脱敏引用、真实初始条件、恢复次数、验证结果、作者执行者、版本与时间。统计包含失败、teacher 接管及未知结果。

不缓存跨快照的索引或坐标，不存任意可执行 JavaScript、任意 selector 或页面生成的指令。流程中的语义控件先经过目录/schema 校验，再由当前观察器绑定。

## 抖音例子的实际执行语义

目标是三个条件同时成立：

```text
审核状态 = 已发布
体裁 = 图文
排序 = 最高播放
```

初始候选流程可以使用已在普通操作中成功完成的顺序：先排序，再审核状态，再体裁。它是候选顺序，不是“排序必然清空筛选”的事实证明。

当一次操作结束时：

1. 读取当前值和加载状态。某个标签临时消失，记录 unknown，暂不点击。
2. 等待相关区域就绪。建议最多三次只读补充观察、共享最多两秒的等待窗口；只有观察器明确判定 `settled` 且必需谓词可读时才继续。无法判定就绪就升级，不凭两张相同的加载画面断言完成。
3. 验证三个条件是否同时成立。条件确实丢失才走已验证的恢复边；否则 teacher 处理。
4. 任务结束后仍校验完整目标。若用户目标是“找出播放最多的作品”，还必须检查结果列表确实对应排序，不能只看排序控件。

例：若经授权的独立试验确认“设置排序使审核状态与体裁重置”，流程才学习为：排序操作将这两个条件标记为待复验；排序就绪后恢复缺失条件。后续网站修复这种行为时，已经满足的条件不会重复设置。

## 批量执行与失败隔离

每个批次共享流程版本，但每项任务拥有独立身份、目标和验证记录。完成 A 不能成为 B 的前置条件证据。

首项或每种不同任务族的首项由调度器判断是否需要 teacher；不能仅凭“同一网站”就共用一条流程。批量动作必须在同一页面、同一参数上下文内，且操作顺序有证据支持；默认仍在每个物理动作后验证，不把整个批次作为不可观察的大操作。

任一项目暴露流程失效时，冻结该版本，并暂停尚未开始且依赖它的项目。已完成项目保留验证记录，不一律重做。不依赖该流程的项目可继续，但同一界面仍只能由一个执行者操作。失败项标记具体状态，禁止报告整个批次全成功。

## 与现有项目的接入点

建议在 `bench/hybrid/` 实现研究层，保持 S6/S7 结果和 P0 MCP 契约不变。

| 模块 | 职责 | 现有接点 |
|---|---|---|
| contracts.ts | 严格流程、观察、交接、预算 schema；拒绝任意代码/未知控件 | 复用公开控件目录与已有预算类型 |
| router.ts | 纯函数计算路由与原因，统一预算和状态优先级 | 接受 S7 decision/error 事件 |
| procedure-store.ts | 原子持久化流程版本、证据、隔离和过期 | 不存密钥/原始页面，借鉴 ledger 的原子写与租约 |
| settle.ts | relevant-region 就绪、三值条件和有界只读等待 | 扩展 observation.ts 的输出；不改变原始 S7 解析器历史结果 |
| controller.ts | 单一动作租约、检查点、累计动作与时间、跨模式终态验收 | 拆出/复用 runPublicSession 的单步受限动作能力；不能反复启动新 session 规避上限 |
| teacher-port.ts | 调用规划宿主、接收受约束步骤与规则草案 | 与 CUA 观察/执行能力分离，不把鼠标工具误当可调用大模型 |
| report.ts | 冷启动、后续重复、恢复、规则命中、各模型成本 | 继承全部开始试次保留原则 |

当前 Jev Key 只能访问 Jev，不能凭它调用另一个大模型。先让当前 Codex 会话通过宿主回调承担 teacher，用于受监督原型。真正无人值守需要宿主支持可调用的 teacher runner，或配置另一模型 API 与其费用授权；这项运行依赖必须在上线前解决，不能只定义一个函数接口就声称全自动。

已有 $3 额度有原截止时间。新设计、离线实现与模拟测试可以继续；新付费实测必须先核对原授权是否仍有效，不能自动延长，也不能把 teacher 的未知会话费用算成零。

## 验收与实验设计

先在可控本地页面注入实际故障，再在授权的真实站点中测迁移。每个故障都验证最终用户目标、真实物理动作次数、未知结果与接管轨迹，不只断言 router 输出。

| 故障/场景 | 必须证明的行为 |
|---|---|
| 首次任务，没有流程 | 自动 teacher；一次示范不会直接晋升 ACTIVE |
| 多个等价合法动作导致 Jev 低置信度 | 输入前接管；不降低门槛，不重复询问同一步 |
| 排序短暂重绘、随后筛选恢复 | 只读等待；不产生重复点击，不学习虚假的重置依赖 |
| 排序稳定后确实重置两个筛选 | 发现不变量丢失；走验证过的修复边或 teacher；不能误报成功 |
| 弹窗遮挡、同名控件、布局改变 | 原绑定失效；流程隔离，重新观察后再规划 |
| 原生隐藏 checkbox | 当前可访问性绑定执行；已选中时不重复切换 |
| 页面永远加载 | 达到等待窗口即升级或有界停止，不无限轮询 |
| 动作已发生但确认丢失 | UNKNOWN；包括 teacher 在内均不得自动重复提交 |
| teacher 自己选择错误或谎称完成 | 独立验收拒绝成功；无额外动作授权 |
| teacher 失败或预算不足 | 有界停止；不重置账本或换执行者绕过额度 |
| 同网站不同语言/账号权限/页面版本 | 不错误复用旧流程 |
| 第 20 项失败 | 暂停依赖该规则的剩余项，前 19 项不重复执行 |

分别比较普通 computer use、原 Jev、混合执行、已验证的确定性流程四组。使用相同起点、独立留出布局/参数与交错顺序；流程在评测前冻结。冷启动的学习、验证、teacher 抽查、失败恢复和费用都计入批次总成本，不能只比较后续最快步骤。报告完整任务成功率、错误动作率、可恢复失败率、UNKNOWN、接管率、规则误命中、p50/p95 和每批总时间。

建议的上线门槛是项目目标而非现有结论：至少 300 个覆盖上述故障的独立任务、没有未授权动作或未决操作重放、逐项最终验证不被跳过，并报告可靠率置信区间；在重复工作负载下，包含学习与接管的整体时间优于普通 computer use。没有达到门槛就保持受监督原型，不以几次示范证明“完美”。

## 首版交付顺序

1. 离线研究层：严格契约、路由、三值状态、共享预算、UNKNOWN 禁重放。先测试，再实现。
2. Teacher 宿主回调与单一执行租约：可控故障页面验证完整恢复，证明切换执行者不会导致重复动作。
3. 版本化流程库与验证门槛：真实批次学习、过期、隔离、只读抽查。
4. 冻结版本做四组对照，再考虑接入长期运行的 MCP 服务。

本轮交付为完整设计与接口/验收边界，不声称这些新增模块已经存在或已通过实测。
