# S8 混合执行实现

2026-10-30。研究模块位于 `bench/hybrid/`，不改变 P0 MCP 服务，也不追溯修改 S7 成绩。

## 已实现

- `router.ts`：严格输入的纯路由策略；调用者不能以模型输出代替可信授权判断。
- `workflow-contracts.ts` / `procedure-store.ts`：目录限定的动作和谓词、账号范围不透明标识、环境指纹、不可变修订、七天以内 TTL。首遍独立验证只产生候选；三次成功且覆盖至少两个真实起始状态才进入 ACTIVE。重复证据、未知结果不计入成功，确认回归隔离流程。
- `controller.ts`：每个界面单一租约，整个任务共享最多 12 次输入、13 次规划、300 秒。新流程、低置信度或状态异常自动触发最多一次 teacher。唯一已验证步骤直接执行，其余由 Jev 选择；所有动作重新观察和绑定，检查前后条件及完整目标。已满足步骤跳过，禁止重复不安全动作。
- `execution-journal.ts`：物理输入前原子写入并同步未决记录。响应丢失、超时或重启后，未决动作保持 UNKNOWN，不因迟到响应自动解除。单独的可信只读核对接口负责解除隔离，规划器没有这个权限。
- `teacher-port.ts`：支持宿主注入规划回调，也支持本地文件请求/响应交接；校验 nonce、请求 ID、截止时间及动作白名单。没有配置 teacher 就停止，不伪造 teacher 成功。

## 真实宿主接入要求

调用 `runHybridSession`，提供固定 catalog、scope、goalPredicates 和可信 adapter。adapter 的 observe 必须从当前可见状态生成三态谓词，不能把“曾经点过”当作仍然成立；bind 必须绑定最新观察；execute 一旦无法确认输入结果必须返回 unknown。

真实设备必须传入 `FileExecutionJournal`，目录按设备/界面稳定保存，不能每题新建来绕过未决记录。该文件存储用独占锁限制多进程，宿主还应统一串行管理所有访问同一设备的外部操作。崩溃遗留 owner.lock 不自动清除；先确认旧进程结束并核对未决记录。不要删账本恢复运行。桌面 `JevSession` 还有独立的 `steps.sqlite`；只调用 `FileExecutionJournal.reconcile` 不会解除步骤隔离，桌面恢复入口是 `reconcileDesktopSession`。

传入 `ProcedureStore` 才启用跨任务证据学习。学习只组合宿主已有动作，不接受任意脚本、坐标回放或新权限。Jev 和 teacher 都只是规划器，必须共享原授权和费用保留器；模式切换不能续期授权。

## 当前限制

这不是独立运行的通用 computer-use 服务。teacher 的模型服务、界面观察器、参数契约和 API 预算接线仍由宿主提供。文件交接只是让当前 Codex 宿主接管的接口，不意味着后台已部署第二个智能体。

完整设计中的动态参数学习、自动生成修复分支及“前十次/每十次”的 teacher 抽查调度尚未实现。当前确认异常走有界 teacher 接管。持久日志和流程库各有 10,000 条历史容量上限，到限停止，不自动删除审计；流程快照累计体积仍需后续压缩设计。

单元测试使用脚本规划器；浏览器集成使用合成页面，不能算真实 Jev/teacher 效果。真实手机报告应分别列出冷启动示范、验证成本、确定性动作、Jev 决策和 teacher 接管，不能把直接执行的耗时称为 Jev 模型速度。
