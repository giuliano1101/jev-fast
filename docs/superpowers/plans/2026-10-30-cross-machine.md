# S10 跨机器 CLI/MCP 实施计划

来源：用户提供的《jev-fast_代码审查与跨机器CLI_MCP设计_2026-10-30.md》。旧审查基线 cecf5fb；实施前将记录 S9 最终提交。检查发现截至 8f01195，src/ 与旧基线一致；S8/S9 的研究代码并不等价于正式 CLI/MCP 接线。

## 交付边界

保留六个公共工具、同一 coordinator/Engine、本地执行。新增中央 decision-only HTTPS 服务与本地 RemoteDecisionProvider。默认 mock、无费用；真实接入必须显式配置并通过持久预算与批准门。离线模拟两设备不冒充两台物理机器部署。

1. A1：生命周期故障测试及修复：open 分配后失败清理；close 失败可重试；shutdown 独立清理。
2. A2：正式 ledger 完整 schema、引用一致性、幂等索引、容量边界；10k/100k 测量与保留策略。
3. A3：内部 decision-v1 严格契约、规范摘要及执行绑定；不更改公开六工具输入。
4. A4/B1：私有 HTTPS decision gateway、本地 remote provider、模式与 health；设备证书绑定短期 agent 凭据，登记/吊销为操作员功能。
5. B2：签名回执，本地绑定/期限校验，在 EXECUTING 同一持久事务消费 nonce，失败关闭；断网本地取消可用。
6. B3：中央预算与决策幂等持久事务；未知供应商调用不重发，重启不清零；live 装配离线假传输验收。
7. B4：doctor/策略状态、CLI/MCP 一致性、双逻辑设备与失败注入测试、说明书、完成报告。
8. C–E：准备 synthetic pilot、真实 adapter/route 契约、发布校验与回滚工具、未安装指南。实际付费 pilot、真实生产观察范围及第二台设备接入需要具体批准/设备条件；不把安卓研究预算自动转用。

每项先故障复现/失败测试，再最小实现，再规格与质量审查。S9 先独立提交。最后执行既有全部离线检查、隐私检查、提交并确认 GitHub CI。

## 验收重点

- 错身份/证书/版本/策略、过期/篡改/重复回执、不同参数同 key、中央重启/丢响应均不触发额外动作。
- 无有效许可不执行，UNKNOWN 不换 key 重放；本地紧急停止不依赖网络。
- 真实参数与目标留在本地，中央只接收最小合成投影及承诺。
- 同 OS 用户权限与宿主绕过不能由 skill 消除；尚无宿主封闭证据时明确 advisory-only。
