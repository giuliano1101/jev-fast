# Jev browser accelerator P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement the attached S0–S5 offline browser MVP, verify every F01–F03 and S01–S15 acceptance gate, then request API setup for S6.

**Architecture:** One local coordinator owns an isolated browser, strict typed tools, persistent write-ahead ledger and fenced goal leases. Providers choose only opaque bound candidates; local policy and independent postconditions decide execution and success. MCP stdio facades authenticate over owner-only local IPC; no public listener.

**Tech Stack:** TypeScript, Node 24, Playwright, Zod, official MCP SDK, Node test runner. Direct fetch for TypeSafe avoids SDK retry layers. Fixed model jev-1.14.0.

Representative acceptance contract:
```ts
assert.equal((await engine.runGoal(client, request)).status, 'SUCCEEDED');
assert.deepEqual(await engine.runGoal(client, request), original);
await assert.rejects(engine.runGoal(client, changedRequest), /IDEMPOTENCY_CONFLICT/);
assert.equal(browser.executions, 1);
```
Each component uses test → expected failure → implementation → passing regression. Boundary faults use controlled fake adapters; browser tests use real isolated Chromium.
