## 实测发现与修改

1. launchd 后台不继承交互式 Codex 的 OS 权限。实际公网读取最初为 false；经用户明确确认并在 Mac 完成本机管理员认证，打开现有 Node 运行时的设备控制与录屏权限。仅重载本次原生 helper 以刷新旧权限缓存，未读取或保存系统密码，未编辑 TCC 数据库。
2. 新前置用户最初无法读取 nginx 的 root-only 公共 CA。复制独立公共 CA 并保持私有权限，原证书及私钥未修改；随后私有预检通过。
3. 地址栏观察后从测试网址变为带额外字符的值，过期按键被 `STALE_OBSERVATION` 拒绝。原请求未重放；保留证据后仅清理自己的测试标签，使用新独立验收继续。
4. Chrome AX 标题是 `Example Domain - Google Chrome`，ScreenCaptureKit 同 PID、同边界的标题是 `Example Domain`。旧严格标题比较导致 `WINDOW_NOT_FOUND`。新增纯元数据匹配函数只归一化真实所属 App 名后缀；仍要求精确 PID、精确矩形和唯一匹配，歧义继续拒绝。离线先复现失败再转绿，实际窄窗口截图复测通过。
5. 原生 stdio 异常退出原本会缓存失效客户端。新桥会标记不健康、收尾自己的进程并由监督器恢复；未完成请求保留 UNKNOWN，旧后台须确认退出，绝不自动重放。相关崩溃/恢复测试通过。
6. 校验调用原本重复经过可选 Mac 健康查询。内部授权只跳过健康信息扩充，仍由原 relay 验证同一 token/会话和开关；真实关闭/撤销回归保留。减少探测没有在本轮证明明显的端到端加速，不据此宣传速度提升。
