# S7 真实网站与本机抖音测试

本阶段在同一本机浏览器（Codex 内置浏览器）和已安装的抖音 App 中执行。没有使用独立 Chrome profile。真实网站为 Wikipedia、Calculator.net；原 timeanddate 日期任务遇到反机器人中间页，该失败保留，未绕过。

题目、完整逐次记录、费用和结论见 [S7 报告](../artifacts/real/report.md) 与 [题库](../artifacts/real/tasks.json)。S6 合成环境测试保持原样，两个阶段不能混合成一个速度指标。

## 架构与边界

- `bench/real/catalog.ts`：固定六道题和公开控件含义，只接收白名单 ID。
- `observation.ts`：本地将当前 AX 界面转换成白名单状态与瞬时索引；原始账号数据不发送给 Jev。
- `decision.ts`：沿用原预算账本、固定官方接口与模型，单次请求，不重试；独立保存用量与失败。
- `optimization.ts`：当前状态推导阶段，合并同一表单内独立准备动作，提交仍单独决策。
- `session.ts`：固定 0.9 置信度、最多 12 个物理动作、300 秒；操作前重新观察，操作后验证，不重放结果不明的操作。
- `cua-adapter.ts`：使用调用方提供的 CUA 句柄，只执行固定的公开测试值和已观察控件。

这是六道题的研究适配器，尚未接入 P0 MCP 的任意真实网站执行。不能把题库内的成功解释为通用桌面智能体。优化包含已知题目的阶段提示与表单模板，不是未见任务泛化测试。原生 App 测试范围是创作者中心的导航和筛选，不覆盖整个抖音功能。

## 复现

先运行 README 中全部无需密钥的离线测试。真实测试需要本机 Codex CUA 控制能力、用户明确授权、可读的对应页面与独立批准的预算。CI 不运行付费实验。

密钥通过 `scripts/enter-api-key.py` 隐藏输入写入本机临时文件；不要粘贴进聊天、命令文本或源码。`decision.ts` 只在明确传入密钥文件与输入 JSON 路径时访问 API。它要求已有的授权预算账本，缺失或过期时拒绝；不要复制旧账本或自行延长原授权。

初始状态、参数、成功信号均写入题库。重置发生在计时外；W2 从中文搜索语言与空查询开始；W3 从默认当天日期、结束日未勾选开始；D1–D3 从内容管理默认筛选与最新发布排序开始。

普通 computer use 由 Codex 通过 CUA 操作。原 Jev 基线逐步在外层代理、CLI 与 CUA 间交接；集成循环通过本地文件队列交给已获网络授权的串行工作进程，调用相同的决策入口；最初子进程直连 DNS 失败的两次尝试已保留，所有界面操作仍经过 CUA。实际执行辅助函数的脱敏副本在 `artifacts/real/cua-runner.example.js.txt`，它依赖当前 CUA 会话绑定，不能当作独立 Node 桌面控制程序运行。

完整时间从首次观察前到可见终态确认，包括模型决策、控件读取、执行、验证、进程启动和调度。旧手工基线还包含外层代理思考与工具交接。因此另外保留一次/题的“集成循环 + 原决策规则”消融对照，区分调度与候选策略变化。第一版和最终修复版分别两次/题，样本很少、顺序分批、站点与缓存会变化；结果是阶段工程证据。

## 数据范围

Jev 仅收到固定题目描述、公开控件名称、当前完成状态 ID 和候选 ID。GitHub 仅保存脱敏决策、时间、公开测试值与公开网站截图。没有上传作品标题、播放统计、账号页面截图、密钥或原始 AX。测试没有发布、删除、上传作品，也没有发送消息或修改账号设置。
