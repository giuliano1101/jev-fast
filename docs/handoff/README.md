# Jev 电脑操控加速层 MVP 开发交接

本包供后续在 Mac mini M4 Pro 64GB 上工作的 Codex 实施。目标是验证：由主 agent 规划、Jev 在合法候选中快速选择、独立执行器执行并验证，是否能改善电脑操控的端到端效率。**本轮交付只有设计文档，没有实现、安装、运行、授权 API 调用或性能结果。**

## 决策摘要

- P0 只做隔离浏览器中的本地模拟表单与导航；默认离线 mock provider，不接触个人浏览器资料或真实网站。
- 共享本地服务提供拟议 MCP 工具与 CLI。支持外部工具的 agent 才可接入；不能替换某产品的内置 CUA 时，不宣称已加速该 agent。
- P0 仅面向 Mac mini 本地支持工具接入的 agent。本地 stdio MCP 不会自动向云端 ChatGPT、Muse 或 GrokBot 提供访问；未来 remote bridge/tunnel 需要单独的网络、鉴权与权限设计，不能为“所有 agent”默认暴露公网。两个测试 client 仅用于并发安全验收，不等于已集成两家真实产品。
- Jev 是 typed decision 服务，不是聊天模型、主规划器或工具执行器。只有通过本地策略过滤的候选才可发给它；其答案无权扩展权限。
- 原生 macOS AX、截图/Box、真实业务操作均不属于 P0。机器配置是目标运行环境，不代表 Jev 权重能本地部署。
- 真实 hosted API 测试是单独的可选阶段，必须等待用户明确同意数据出境范围、预算和密钥安全配置；当前未获授权。

## 完成定义

离线 P0 完成意味着可复现的 fixture、安全状态机和两个 MCP 客户端冲突测试通过，且提供真实运行产物。它**不等于**已证明 Jev 加速。只有获授权的真实模型对照实验才能评价 Jev 效果；负结果也须保留。
